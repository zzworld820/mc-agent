# mc-agent

基于 [mineflayer](https://github.com/PrismarineJS/mineflayer) 的 Minecraft NPC Agent。

**当前能力**：陪玩与自主运行——

- **陪玩模式**（公网服用）：NPC「阿方」能聊天，还能**听懂一句话、自己拆成几步做完**
- **自主生存模式**（默认，实服持续验收中，尚未完成全流程）：无需玩家消息，循环处理危险、补给、工具、住所、基础农田和鸡牛羊牧场。可用 `AUTONOMY_MODE=milestones` 切回旧装备与下界路线，详见[第 9 节](#9-自主运行模式)。

陪玩模式的例子：

> 「阿方 帮我砍4个木头，砍完给我」→ 找树 → 走过去 → 砍 → 捡掉落物 → 走回来 → 把木头扔给你 → “4个橡木都给你了，收好哈”
>
> 「阿方 再砍3个木头，做一个工作台给我」→ 砍树 → 合成木板 → 合成工作台 → 送过来

干活的时候还能照常聊天（“你在干嘛？”“砍木头呢，3/10 了”），随时喊「停下」立刻停。饿了自己吃东西，僵尸贴脸会还手。

> **陪玩模式规则**（关闭自动自主模式时）：普通采集工具只在玩家要求时挖天然方块；原木额外检查树叶；普通寻路不挖不搭；战斗工具不攻击玩家和动物。自主生存模式会主动采集、建设，并在暂缺农作物食物时尝试临时打猎；相应开关见配置表。

## 1. 全局图：它是怎么工作的

```
游戏服务器（你们的世界）
   ▲
   │  Minecraft 协议
   ▼
bot.js ──────────────── 连接 / 断线重连（mineflayer 负责“假装成一个玩家”）
   │  进服后挂上三层能力
   ▼
┌─ chat/  ─────────────── “大脑”：听玩家说话、收任务结果 → 问大模型 → 回复 / 下指令
│   chatHandler.js       两个触发源：玩家消息、后台任务结束
│   agentLoop.js         Agent 循环（ReAct）：大模型 ⇄ 工具，直到给出回复；还会检查“只说不做”
│   persona.js           人设 + 规矩 + 当前状态（血量、背包、在做什么）
│   memory.js / llm.js   每个玩家的对话记忆 / 调大模型 API
│
├─ actions/ ───────────── “手脚”：感知、记忆、移动、采集、战斗和自主工具
│   taskManager.js       后台任务：耗时的动作在后台跑，聊天不卡；一次一个，可随时取消
│   perception.js        看周围、找方块、看背包（瞬间完成）
│   movement.js          过来、跟随、去坐标、停下
│   gathering.js         挖方块（白名单 + 真树检测）、捡掉落物
│   items.js             送东西、拿装备、合成
│   combat.js            打敌对怪物
│   building.js          建造山洞避难所、低成本 starter 小屋（门、窗、照明）
│
└─ behaviors/ ─────────── “本能”：不用想就会做的反应
    survival.js          饿了吃东西、怪物贴脸还手、死了取消任务
```

### 一件多步骤的事是怎么做完的

```
玩家：「阿方 帮我砍4个木头，砍完给我」
  │
  ▼ 第 1 次思考（玩家消息触发）
大模型 → collect_block(log, 4)  ──> 后台任务开始，工具立刻返回“已开始”
大模型 → “好，这就去砍”          ──> 发到公屏
  │
  │   ……后台：找树 → 走过去 → 砍 → 捡，玩家这时说“你在干嘛”也能马上得到回复……
  │
  ▼ 第 2 次思考（任务结果触发）
【任务结果】挖了 4 个方块，背包新增 oak_log x4
大模型 → give_item(玩家, oak_log, 4) ──> 后台任务：走过去、扔给他
大模型 → “砍好了，这就给你送过去”
  │
  ▼ 第 3 次思考（任务结果触发）
【任务结果】已经把 oak_log x4 扔到玩家脚边
大模型 → “4个橡木都给你了，收好哈”
```

**关键点**：大模型自己不会动手，它只会“提要求”；真正动手的是 `actions/` 里的代码。耗时的动作在后台跑，干完把结果再喂给大模型，它就能接着规划下一步——这就是 Agent 的核心循环。

几个让它“靠谱”的小机制：

- **只说不做自检**：大模型偶尔回“这就去”却没调用工具。`agentLoop.js` 发现这种情况会提醒它一次，让它真的去做或改口
- **停下快速通道**：玩家说“停下 / 别跟了 / 算了”时，不等大模型思考（1~3 秒），先立刻停住
- **自动续做上限**：没有玩家插话时最多自动连做 6 步，防止失败后反复重试停不下来
- **够不着的方块记 10 分钟**：换个说法再叫它，也不会在同几个够不着的方块上原地打转

### 技术选型（以及可以替换成什么）

| 层 | 现在用的 | 作用 | 常见替代 |
|---|---|---|---|
| 游戏客户端 | mineflayer | 用代码模拟一个玩家：进服、聊天、移动、挖方块 | 写 Fabric/Forge 模组做真 NPC（要 Java）；参考项目 [mindcraft](https://github.com/kolbytn/mindcraft)、Voyager 也都基于 mineflayer |
| 大模型 | DeepSeek（OpenAI 兼容接口 + function calling） | 理解玩家的话、决定做什么、组织回复 | 通义千问、Kimi、OpenAI、本地 Ollama —— 改 `.env` 里 3 行即可（模型需支持工具调用） |
| 寻路 | mineflayer-pathfinder | 给个目标，自动算路线、绕障碍 | 手动 `setControlState` 控制前后左右（只适合很简单的场景） |
| Agent 循环 | 手写（`agentLoop.js` + `taskManager.js`） | 大模型 ⇄ 工具、后台任务、任务结果回流 | LangChain.js / Vercel AI SDK 等框架（封装好了，但看不到原理） |
| 配置 | dotenv | 从 `.env` 读配置和密钥 | Node 自带的 `--env-file` |
| 测试服 | Paper 1.21.6（`npm run test-server` 自动下载） | 和公网服同版本的真服务端，能测移动、砍树、打怪 | flying-squid（`npm run test-server:lite`，纯 Node，但看不见玩家、没有树） |

## 2. 快速开始

需要 **Node.js 22**（mineflayer 官方要求；Node 20 实测也能跑）。

```bash
git clone https://github.com/xiaoye7777/mc-agent.git
cd mc-agent
npm install
cp .env.example .env     # 然后编辑 .env，至少填上 LLM_API_KEY
```

### 方式 A：本地测试服（推荐，改了代码先在这测）

需要 Java 21 或更新（`brew install openjdk`）。

```bash
npm run test-server      # 终端 1：第一次会下载 Paper（约 50MB）并让你确认 Minecraft EULA
npm start                # 终端 2：启动 NPC（.env 里 MC_HOST=localhost、MC_PORT=25565）
```

然后用游戏客户端（1.21.6、离线账号）连 `localhost` 进去。在测试服终端里敲 `op 你的名字` 给自己管理员权限，就能用 `/time set day`、`/give`、`/summon zombie` 布置测试场景。

测试服的设置（`local-server/server.properties`，第一次启动时生成）：离线模式、简单难度、出生点不保护（NPC 能在出生点附近砍树）。存档在 `local-server/`，不进 git，删掉这个目录就是一个全新的世界。

> 只想测聊天、不想装 Java：`npm run test-server:lite` 起一个纯 Node 的简易服务端（1.21.4）。它看不见玩家、没有树和怪，只能测聊天。

### 方式 B：进你们真正的世界

在 `.env` 里改 `MC_HOST` / `MC_PORT`，然后 `npm start`。按服务器类型选：

| 服务器 | 怎么设置 |
|---|---|
| 单人世界「对局域网开放」 | 游戏里开放后会显示端口号，填到 `MC_PORT`。**你自己必须是离线账号登录**（HMCL 的离线模式），否则 NPC 进不去 |
| 自己开的服务端 | `server.properties` 里设 `online-mode=false`，`MC_AUTH=offline` |
| 正版服 | `MC_AUTH=microsoft`，`MC_USERNAME` 填一个正版账号邮箱，首次启动按提示在浏览器登录 |

### Web 监控与临时任务

`npm start` 会先构建三维页面，再启动 Agent 和本地监控服务。打开 **http://127.0.0.1:3000/**，可以查看生命、饥饿、坐标、当前阶段、完成项与缺口、背包和已观察到的箱子库存，以及寻路失败和停滞记录。箱子内容带有观察时间，未重新打开的箱子不能视为实时库存。

页面提供第一人称、第三人称和俯视三维画面，并显示已知路径、活动轨迹与建筑范围。画面使用 Agent 已加载的真实区块；当前适配 Java 1.21.6，使用 1.21.4 素材并为部分新增植物提供近似外观，模组新增方块的模型可能缺失。

对话框分为「对话」和「临时任务」：对话只查询状态；临时任务默认优先级 80，高于主任务的 50，接管前保存主任务检查点，完成、失败或取消后恢复主任务。危险处置仍优先。优先级、暂停和恢复都可在页面调整。任务历史按 Agent 与世界保存到 `data/web/`；重启时记录被中断的临时任务，避免重复执行交付等动作。

默认仅监听 `127.0.0.1`。可在 `.env` 中设置 `WEB_ENABLED`、`WEB_HOST`、`WEB_PORT`、`WEB_VIEW_DISTANCE`、`WEB_TEMPORARY_PRIORITY`、`WEB_PRIMARY_PRIORITY`。大模型密钥只保存在后端 `.env`，不会发送给浏览器。

多 Agent 使用同一网页。复制 `agents.example.json` 为 `agents.local.json`，在 `.env` 设置 `AGENT_PROFILES_FILE=agents.local.json` 以及各档案引用的密钥环境变量，随后运行 `npm start`。每个档案需要独立的 Minecraft 账号，可设置不同的接口地址和模型名。网页只显示模型名与密钥是否已配置。省略档案文件设置时沿用单 Agent 配置。

在顶部切换 Agent 后，任务、库存、对话和三维视图均跟随所选 Agent。盖房、基地设施和农田显示当前操作步骤。卡顿与处理历史按 Agent 追加到 `data/web/<id>-incidents.jsonl`，面板显示最近 80 条。两游戏日卡顿计时只累计有可执行任务的时间，避险或正常等待暂停计时，空闲会清除本轮计时。

若直接运行生存测试脚本或 `npm run dev`，首次及修改三维源码后先运行 `npm run build:web`；已有生存测试进程时直接访问网页即可，无需再启动一个 Agent。

## 3. 能对它说什么

在公屏说话时带上「阿方」或「AgentBot」，或者私聊 `/msg AgentBot ...`。不用背命令，正常说话就行，下面只是例子：

| 你说 | 它会 |
|---|---|
| 阿方 过来 / 跟着我 / 停下 | 走到你身边 / 一直跟着你 / 立刻停下手上所有事 |
| 阿方 去 100 64 -20 | 走到坐标 |
| 阿方 帮我砍点木头 / 挖点沙子 | 找到最近的天然方块，挖完捡起来，告诉你背包多了什么 |
| 阿方 砍5个木头给我 | 砍完自己走过来扔给你 |
| 阿方 给我做个工作台 / 做几根木棍 | 用背包里的材料合成（工具类要站在工作台旁边） |
| 阿方 有僵尸，帮我打 | 拿上最好的武器去打 |
| 阿方 把地上的东西捡起来 | 捡附近的掉落物 |
| 阿方 建一个山洞避难所 | 找天然山体挖小房间，安装门、火把、工作台和熔炉（需开启自主能力） |
| 阿方 盖一间基础小屋 | 自动准备低成本材料，建 7x7 石木小屋、门、玻璃窗、床位和储物/加工区（需开启自主能力） |
| 阿方 有哪些房型 / 有哪些房屋工程 | 查询房型特征、材料阶段、扩建模块，或已有工程坐标和状态（需开启自主能力） |
| 阿方 扩建小屋 / 向上加一层 / 建地下储藏室 | 保留已有主体，追加翼房或梯井连接的上下层（需开启自主能力） |
| 阿方 查看农场 / 把农田扩到 7×5 / 成熟九成再收割 / 整理仓库 | 通过农场工具查看、配置或安排自主巡检、扩田、存料（需开启自主能力） |
| 阿方 周围有什么 / 这里是什么群系 / 附近有村庄吗 | 查看状态、维度、群系和多方块对象候选，不自动移动或采集 |
| 阿方 你背包里有啥 / 你在干嘛 | 看一眼再如实回答（干活时会说进度，比如 3/10） |

### 长期记忆框架（MongoDB，默认自动初始化）

设计链路：`Agent / 工具 → MemoryManager → MongoDB`。大模型不接触连接凭证和原始数据库查询。
短期聊天仍由 `chat/memory.js` 保存在进程内，不将每次聊天或所有方块复制到数据库。

核心约定：

- 稳定的 `AGENT_ID` 与名字分开；改名不应更换身份 ID。身份档案保存于 `agents`，角色和故事设定来自配置，不冒充亲历事件。
- 世界优先使用显式 `WORLD_ID`，其次接受服务端提供的持久标识；两者都没有时自动建立本次连接的临时隔离分区，不依赖地址、端口或种子猜测复用。种子作为字符串元数据保存于 `worlds`，避免大整数精度丢失。
- 世界内记录按 `worldId + dimension + epoch` 分区。新开档/独立副本使用新 ID；原存档迁移保留 ID。
- 回档后统一更新 `WORLD_EPOCH`；旧 epoch 仍可查询，但标记 `needsRevalidation`，建筑入口不会自动继续旧 epoch 工程。
- `private` 仅作者本人、`team` 仅同团队、`world` 同世界共享；只有 `knowledge` 可以用 `global` 跨世界共享。
- 作用域由管理层按可信运行配置过滤。不同作者的观察独立保存，不把别人的记忆覆写成自己的经历；同一对象的跨作者冲突自动裁决尚未实现。
- 种子相同不合并存档；`PARENT_WORLD_ID` 只记录副本来源，不自动复制或合并记忆。

#### 自动初始化与可选配置

安装项目依赖，并准备可连接的 MongoDB 服务。本改动只加入客户端驱动，不自动部署或启动数据库。
默认进服自动连接本机 MongoDB，首次运行自动生成 Agent ID 并保存在 `data/memory/profiles/`。
本地身份档案默认按 `MC_USERNAME` 选择；只改 `NPC_NAME` 不影响身份。多 Agent 使用不同账号或 `MEMORY_PROFILE`。
如需固定世界关联、共享团队或连接远程数据库，可在 `.env` 中配置，例如：

```dotenv
MEMORY_ENABLED=true
MONGODB_URI=mongodb://127.0.0.1:27017
MEMORY_DATABASE=mc_agent
AGENT_ID=afang-001
AGENT_TEAM_ID=builders
WORLD_ID=survival-main-001
WORLD_NAME=共同生存世界
WORLD_EPOCH=initial
```

这些 ID 是可选的人工覆盖示例；可使用 UUID，关键是稳定且唯一。同世界的不同 Agent 使用相同的持久世界 ID。
同团队配置相同 `AGENT_TEAM_ID`；更换游戏账号但保留角色时，指定原 `MEMORY_PROFILE` 或原 `AGENT_ID`。
迁移 Agent 到其他机器时，应携带身份档案或设置原 ID。切换存档或测试服时，不要沿用另一个存档的显式 `WORLD_ID`。
默认 `MEMORY_ENABLED=true`；显式设为 `false` 仍可关闭，不自动覆盖已有 `.env` 的选择。
MongoDB 启动时不可用，游戏仍继续，自动记忆暂不上线；下一次显式记忆查询/保存会重试连接，或重连游戏时重试。
数据库故障不会被伪装成“保存成功”。自动队列有界且不保证离线不丢失，未上线期间不会假装已记录观察。

#### 世界自动识别的边界

原版客户端连接信息不足以证明两个连接是否对应同一份存档，种子相同也不能证明。
因此临时分区每次连接生成新 ID，并明确提示，不能在重连后自动找回之前的世界内记忆；Agent 身份和通用知识不因此改变。
需要完全自动且可跨重连续接时，服务端适配器须为存档持久保存一个世界 ID，并在进服时通过自定义通道
`mc_agent:world_identity` 下发 UTF-8 JSON：`{"worldId":"存档的持久UUID","epoch":"initial"}`。
客户端已接收此通道，进服最多等待一秒；本仓库当前**不包含服务端 Fabric 身份插件**。
没有适配器时，为该存档设置一次 `WORLD_ID` 也能稳定续接，无须每次进服重新填写。
已采用服务端身份的连接如果收到不同世界 ID 或 epoch，记忆会暂停，重连后重新识别。

`memories` 的通用信封保存类型、逻辑 key、世界、维度、epoch、作用域、作者、来源、观察时间和类型详情。
当前按作者、分区、作用域和 key 生成记录 ID，重复观察更新自己的同一条记录；事件采用独立 ID。
复杂结构的候选分类不会因存入数据库而变成已确认事实；`personalExperience` 也不代表分类一定正确。

#### 已预留的类型与边界

管理层提供 `rememberPet`、`rememberFacility`、`recordContainerSnapshot` 等类型接口。
设施可表达农场、牧场、仓库、刷铁机等，区分建造者/所有者/管理者及“建成待验收”和“运行正常”。
宠物接口要求持久 UUID，保留最后位置与未知状态；不使用短期实体编号猜测个体。
容器接口保存槽位快照并比较物品名、数量和 metadata，变化只能记为未解释变化，不推断是谁操作。
**宠物驯服/归属识别、实际开箱快照接入、自身存取归因、完整 NBT 差异、方块拆除失效、设施验收、故事线推进、知识自动评价尚未实现。**
记忆接口本身不执行养殖、种田、囤货、存箱或建设机器；基础农牧行为由自主生存控制器单独执行。

旧 `data/building/projects.json` 保留不动：关闭或数据库未上线时仍使用本地工程记录；自动世界分区存在时按该分区保存，不串到其他连接。
数据库后来上线后不会自动合并这些离线工程，避免出现两个来源相互覆盖；原文件保留供明确迁移。
旧 JSON 尚无自动迁移工具；需要明确确认世界对应关系后再迁移。房屋模型仍使用 JSON，不进入动态记忆。
全量世界地图、语义向量检索、自动学习、自动合并矛盾记忆、细粒度数据库用户授权均不在本版框架内。

### 语义感知（只读）

保留 `find_block`、`check_inventory`，新增 `get_world_state` 和 `scan_environment`。
`look_around` 保留原有玩家、生物、掉落物和方块摘要，同时增加维度、群系和对象候选摘要。
每次思考的简短状态也包含当前维度与群系；详细扫描仅在工具调用时执行。

- `get_world_state`：生命、饥饿、饱和度、氧气、背包、坐标、维度、当前位置群系；未知值为 `null`。
- `scan_environment({ target: "all", radius: 24 })`：默认半径 24 格，最大 32 格；可限定一种对象类型。

当前识别类型：

| 类型 | 识别对象与主要证据 |
| --- | --- |
| `tree` | 连通原木、竖直树干和附近天然树叶；返回树种、已观察原木数与局部范围 |
| `river` / `water_body` | 连通水面或冰面；结合河流群系区分河流与一般水域，不凭一块水或细长外形下结论 |
| `house` | 门、成组建材及窗户/床/生活设施组合，仅作为房屋候选 |
| `village` | 分散的多个入口、多张床，结合钟、道路、农田和村民等证据 |
| `nether_fortress` | 下界砖主体、栏杆/楼梯，结合下界疣、刷怪笼或相关生物 |
| `bastion_remnant` | 黑石砖主体，结合镶金黑石、装饰、财物或猪灵 |
| `stronghold` | 主世界石砖组合，结合传送门框架、虫蚀石砖、铁栏杆或书架 |
| `desert_pyramid` / `jungle_temple` | 沙漠神殿的砂岩与陶瓦图案；丛林神庙的苔石与机关组合 |
| `ocean_monument` | 海晶石建筑、海晶灯与水域组合 |
| `ruined_portal` | 黑曜石、哭泣的黑曜石与周围下界材料组合 |
| `mineshaft` | 铁轨、木支撑和蜘蛛网组合 |
| `end_city` | 末地紫珀与末地石砖建筑，结合末地烛或潜影贝 |

扫描读取**已加载客户端区块**，不保证视线可见，不读取种子或调用 `/locate`。
复杂结构结果统一是 `inferred` 候选；`confidence` 是规则证据等级，不是统计概率。
结果带有证据数量/样本、证据边界、扫描起止时间、采样上限及解释局限。
树干和水面使用有界连通搜索，触及边界或数量上限时标记 `partial`；`evidenceBounds` 不代表完整建筑边界。
没检出不代表不存在，仿建、损毁结构、密集相接树木和证据超出范围都可能造成误判或漏检。
河流只识别局部表面，不推断水深、流向或可渡性；建筑不推断归属、箱内物品、未观察的房间或陷阱状态。

这些改动**不改变采集数量、整树采伐、补货、囤货、存箱或其他行动策略**。
新增结构可以在 `structures.js` 添加类型、适用维度、特征组、数量阈值和组合条件，自动进入扫描工具的类型清单。

### 房屋模型与扩建框架

建造入口不再绑定一个尺寸：`list_house_models` 查询房型，`build_house({ modelId })` 按模型施工；旧参数 `style: "starter"` 仍兼容。
`list_house_projects` 查询工程，`expand_house({ projectId, moduleId, direction })` 选择工程和模块；direction 为 `back`（默认）、`up`、`down`。垂直层以梯井连接，地下室保留天然围墙和原地板作顶板；旧矩形工程也可使用继承其占地的垂直适配器。

当前内置两种房型：

| ID | 特征与用途 | 主体 | 默认扩建模块 |
| --- | --- | --- | --- |
| `starter` | 早期石木生存屋；目标 4 个箱子、3 个熔炉、2 张床、1 个工作台 | 7×7 | `utility`：7×5 通用功能翼房 |
| `warehouse` | 石木仓储工坊；目标 6 个箱子、6 个熔炉、1 个工作台，不默认摆床 | 9×9 | `storage`：9×7 仓储翼房 |

家具数量是布局目标，不是已放置数量。材料或空位不足时记录原因；床只使用已有物品。
各段预留中央通道；翼房先封好外壳，再开两格高的连接门洞，不拆原主体。
可重复模块会向后连续追加，未完成模块优先恢复，而不是重叠施工。

#### 工程记录与后续学习

`data/building/projects.json` 保存工程 ID、服务器/维度、模型完整快照、坐标、各段状态和施工反馈。
模型更新或删除不会修改已有工程快照。中断后的再次调用可使用旧快照继续；旧版本未记录的 starter 主屋可保守识别接入。
服务器按连接地址和端口区分，同地址换新世界时应备份并移走旧工程文件；运行时仍重新检查地基和占用。
本地数据默认被 Git 忽略，分享模型时单独导出 JSON。当前存储面向单个机器人进程，进程内串行写入并原子替换文件。

后续学习器可用 `listBuildingExperiences` 读取施工反馈，用 `deriveHouseModel` 从父模型派生候选，
再用 `saveHouseModelDraft` 保存为 `draft`，保留父模型 ID 和版本。草稿不出现在可施工目录。
`ready` 表示可被施工入口选择，不代表已经实测通过；候选评估完成后再将模型状态更新为 `ready`。
目前**没有实现自主观察建筑、审美评分、训练或自动创新闭环**，只提供经验数据、模型谱系和候选接入基础。

## 6. 怎么加新动作（最常见的扩展）

动作 = 一个对象 `{ name, description, parameters, run(ctx, args) }`。写好后加进 `src/actions/index.js` 的 `ACTION_GROUPS`，**聊天和 Agent 循环一行都不用改**，大模型自动就会用。

`ctx` 里有：`bot`（mineflayer 机器人）、`tasks`（后台任务）、`player`（谁让做的）、`isWhisper`、`options`（开关）。

**瞬间完成的动作**直接返回一句结果：

```js
{
  name: 'say_time',
  description: '告诉玩家现在游戏里几点。玩家问“几点了”时使用。', // 写清楚“什么时候用”，大模型靠这个判断
  parameters: { type: 'object', properties: {} },               // 参数的 JSON Schema
  run({ bot }) {
    const hour = (Math.floor(bot.time.timeOfDay / 1000) + 6) % 24;
    return `现在大约 ${hour} 点`;                                // 这句会交给大模型看
  },
}
```

**耗时的动作**放进后台任务，立刻返回“已开始”；干完的结果会自动交给大模型决定下一步：

```js
run({ bot, tasks, player, isWhisper }, { x, y, z }) {
  tasks.start({ label: `去 ${x} ${y} ${z}`, kind: 'move', owner: player, isWhisper, report: 'always' },
    async ({ signal, setProgress }) => {
      await goTo(bot, new goals.GoalNear(x, y, z, 1), { signal });  // signal：被“停下”时会中断
      return '到了';                                               // 抛错 = 失败，错误信息也会交给大模型
    });
  return '已出发';
}
```

写耗时动作的三条规矩：经常检查 `signal`（用 `helpers.js` 里的 `goTo` / `sleep` 会自动处理）；错误信息写中文、写清楚原因（大模型要拿它跟玩家解释）；会改动世界的动作先想清楚安全规则。

## 9. 自主运行模式

### 默认：无人干预的基础生存循环

```dotenv
NPC_AUTONOMY=auto
AUTONOMY_MODE=survival
```

进服并加载基础区块后自动开始，不需要玩家聊天或 LLM 密钥。
如果旧 `.env` 明确设置 `NPC_AUTONOMY=off`，需将其改为 `auto` 才会自动开始；`on` 则等待手动启动。
玩家叫停或下达替代后台任务会取消当前循环，本连接不会偷偷自动重启；断线后旧任务取消，新连接按配置重新启动。
`NPC_ALLOW_DIG=false` 会阻止启动建设型自主模式；战斗关闭时不通过打猎绕过开关。

策略优先级为危险处理、进食/恢复、基础工具与加工、住所、农田、房屋和牧场维护。
这不是严格执行一次的脚本：饥饿、受伤、敌人接近和缺氧可打断当前步骤，脱险后根据实际状态继续。
同一主要目标在执行期间不会因看到新资源就被随意替换；每个步骤有四分钟预算，缺资源或失败会退避，适当短距离探索。
首次优先木器、工作台、石器和熔炉；有安全山体时挖洞，否则尝试已有的基础房屋施工器。
夜晚已有住所时返回并关闭档案中的入口，不使用旧睡眠技能的挖坑回退逻辑。

| 子系统 | 本轮实现 |
| --- | --- |
| 风险 | 生命、食物、自己的氧气、护甲覆盖、局部视线遮挡、敌人距离/接近趋势、近处来袭投射物、火焰/熔岩/危险接触和坠落信号 |
| 避险 | 先中断技能，尝试可达的已知住所，再尝试有支撑的局部退路；低氧上浮，着火时尝试附近浅水；连续安全五秒后再评估 |
| 自卫 | 装备和生命条件允许时短时近身防御，不主动追怪；条件不足时撤退，避免与播种、进食和持饲料争抢手持物品 |
| 农业 | 可配置起始尺寸和最大尺寸，按日巡检、成熟率收割、补种、修补土层/照明/灌溉；满足种子、收获和时间条件后渐进扩田 |
| 仓储 | 农田旁简易棚或自有房屋箱位，余料入库、材料优先出库，核对转存数量并保存实际打开时的容器快照；空间不足时有限扩建 |

| 畜牧 | 为鸡、牛、羊分别建立 5×5 围栏，布置门、持对应饲料引导、观察入栏并关门；识别成年个体时有条件尝试繁殖 |
| 繁殖结果 | 设置尝试间隔，观察新幼体；未观察到幼体就标记未确认，不把喂食当作繁殖成功 |

### 生存补给管理（代码已接入，未实服验收）

`src/supplies/` 将身体饥饿、随身口粮、自有仓储和任务准备统一管理，复用原有农业、采集、冶炼和仓储技能。新逻辑不依赖大模型每次提醒。

| 任务 | 默认随身口粮目标 | 其他准备 |
|---|---|---|
| 基地附近工作 | 16 点，最低余量 8 点 | 按任务需要工具 |
| 长途移动 | 至少 40 点 | 结合目的地计算往返余量 |
| 采矿 | 至少 40 点 | 24 个火把、可用镐子；火把低于 8 个暂停补给 |
| 探索准备 | 至少 48 点 | 按照明、预计时长和危险程度增加要求 |

口粮单位为食物可补充的饥饿值点数，不是物品个数。预算按任务类型、距离和预计时长作保守估计，不保证精确耗尽时间；未来作物不算口粮，仓储快照不算随身库存。中风险任务检查基础武器，高风险任务还准备至少两个护甲部位；任务运行途中检查工具是否将近损坏。

- 默认饥饿值低于 18 或受伤需要补充时选择进食；低于 12 且无可食用口粮会打断工作，随身粮低于任务最低余量也会提前暂停。直接危险优先脱离，不能边挖掘、边开箱、边由另一个循环抢手吃东西。
- 优先使用随身食物；比较附近仓储和加工成本，再尝试自有农田、加工和有限范围找食物。自动发现自有房屋模型的箱位，连同农田仓储统一查询；未加载的预期箱位必须实际到达验证，不打开随机玩家箱子。空箱或不可达来源进入冷却，正常粮不足则暂停非必要工作而不是反复冲同一个箱子。
- 土豆、胡萝卜按种植规模保留材料，紧急时允许食用并记录恢复种植材料的欠账；腐肉可在饥饿值不高于 6 或低生命急需补给时应急食用，但不计入正常出行口粮。蜘蛛眼、河豚、毒土豆等不会因为“能吃”而自动使用。相关阈值在 `.env.example` 的 `SUPPLY_*` 中配置。
- 自主生存的工作目标因补给暂停后保留目标和位置，补足后按真实工程/农田状态继续。显式采集、建造、较远移动、跟随和战斗任务也接入准备/打断；附近 16 格内的普通短距离移动不强制凑满口粮再出发，保留基础进食反应。声明了地下或风险要求的短途任务仍按预算准备。同一次运行中自动恢复，采集记录已挖数量，不重新采满整份订单。没有正常食物来源时会保留暂停状态，不能保证任意世界都能成功补给。
- 手动任务的描述和采集进度保存到既有世界分区检查点；重启后可显式调用 `resume_supply_task` 恢复剩余部分。玩家叫停仍然有效，交付物品等不适合重放的动作不自动重试。任务切换会等待旧任务退出，避免新旧任务交错控制容器和寻路器。
- 仓储按当前任务的总口粮预算留粮，不再对每种食物各留 16 个；种植材料和所需火把另行保留。箱子取出数量同时核对背包增加与容器减少。库存变化仍只标记观察结果，不推断是谁动过箱子。

可用工具：`inspect_supplies` 只读查看库存和任务缺口；`prepare_supplies` 为指定任务准备，不代替执行探险；`resume_supply_task` 显式恢复中断任务。`go_to` 可附带 `profile: 'expedition'/'mining'`、`needsLight`、`expectedMinutes`、`risk`，让实际出行接受对应预算检查。`NPC_AUTONOMY=off` 时不启用主动补给包装，只保留原有基础生存反应；挖掘和战斗开关继续生效。

本轮不运行行为测试或服务器。语法/静态检查通过也不代表饥饿应急、容器交互和任务恢复已经实服验收。

### 农场循环与配置（代码已接入，未实服验收）

默认从 **3×2 占地**开始，最大自动扩到 **15×15**；内部水槽和灯位会占用一部分面积，所以占地不等于净种植格数。支持小麦、土豆、甜菜和胡萝卜；小麦种子可以打草尝试获取，其他作物需要世界中实际取得种植材料，不会凭空生成。

自主生存白天每天优先安排一次农田检查，收到 `wake` 事件后也会检查；另外默认每 1200 游戏刻复查。流程为：

```
生存紧急情况优先 → 到田边观察 → 修补水槽/土层/照明
→ 成熟率达到阈值时分批收割 → 捡取并补种 → 保留种子与随身物资 → 余料存箱
```

- 默认阈值 `FARM_HARVEST_RATIO=0.9`，即已种植作物中至少九成成熟才启动一轮收割，只收已成熟作物，不铲未成熟苗；设为 `1` 则要求全部成熟。未加载区域不参与猜测，全部观察清楚后才启动整批收割。紧急饥饿时允许先取成熟作物救急。
- 收割目标列表先存档，危险中断或重启后接着本批收割，不因刚补种的幼苗拉低成熟率而卡住。背包空间不足先尝试存料，不能腾出空间就暂缓采收。
- 只修已记录的自有地块和设施；浅坑可补土后重耕，水槽可修底/侧面并补水，缺灯补灯，缺苗补种。深坑、未知建筑占用、液体风险、缺少材料等会记录原因并暂缓，不强拆未知结构。
- 至少完成一轮收获、种子有余量且仓储未满后，每隔 `FARM_EXPANSION_DAYS=2` 个游戏日尝试向一边追加 `FARM_EXPANSION_STEP=2` 格。扩建位置不安全则保留旧田；没有鸡牛羊不妨碍满足条件的农田扩建。
- `FARM_STORAGE_MODE=shed` 默认建农田旁简易仓储棚，不是封闭防怪房；`home` 使用自己的房屋工程箱位。箱子默认 2 个，上限 12 个。棚子追加箱位；室内空间不足按 `FARM_STORAGE_DIRECTION=up/down/back` 加层、地下室或翼房。保留种子、食物、工具等随身储备，其他余料入库，后续缺材料优先取库内已有材料。
- 容器内容仅在真正打开箱子时更新，并核对转存前后数量。两次打开之间发现变化仅标记“未解释的变化”，不会声称知道是谁动过箱子。农田、仓储及配置随既有 Agent/世界/维度分区持久保存；跨连接续接仍需要稳定世界身份。

配置详见 `.env.example` 的 `FARM_*` 项。聊天可使用 `configure_farm` 调整本世界规则，`inspect_farm` 查看状态，`manage_farm` 安排 `tend/expand/store`；例如 `manage_farm({ operation: 'expand', width: 7, depth: 5 })` 只增加地块，不拆旧田。已有农田不自动缩小，修改 `storageMode` 不会搬迁已有箱子。每次仓储维护最多追加一段，达到箱数上限后保留余料、记录未入库状态，不无限建设。

本轮仅做静态语法与补丁检查，未启动游戏、Fabric 服务器或行为测试；施工/设施记录仍不代表实服验收通过。

运行检查点保存在 `data/strategy/`，并在记忆在线时排队同步 MongoDB。
恢复时只比较同一身份、世界、维度和 epoch 的检查点，选择较新记录；数据库离线不阻塞紧急撤退。
重连能否恢复仍取决于持久世界 ID；临时会话分区不会被猜测合并。

本版以规则和既有依赖规划器为主，未加入 LLM 自我聊天、策略学习、养殖自动屠宰、产物仓储、设施自动扩容或复杂机器。
牧场只避开明显命名动物和附近已有围栏的候选，不能据此外推真正产权；饲料、可引导动物、平地、水源都可能暂缺。
引导和繁殖依赖游戏 AI、实体元数据和服务器实际更新；未知成年状态时不盲目喂食。
风险识别和局部遮挡检测是启发式，不是完整战斗模拟；无可达退路、严重坠落或持续伤害时仍可能死亡。
死亡后不沿用失去的背包物品，重生后重新评估基础需求；本轮未增加危险尸体回收策略。
**本轮不运行测试或服务器，仅做代码审阅和静态语法/格式检查，不能据此声称已实现实测无人长期存活。**

### 可选：旧里程碑发育模式

使用 `AUTONOMY_MODE=milestones` 运行以下旧路线；工具 `start_autonomy` 也接受 `mode: "milestones"`。

```bash
npm run test-server   # 终端 1：本地 Paper 测试服
npm run survive       # 终端 2：NPC 进服后立刻从空手开始发育
```

`survive` 会**强制连本地测试服**（不会用 .env 里的公网地址），因为发育要大量挖方块、放工作台和熔炉。也可以用陪玩模式的 NPC 说「阿方 自己去发育吧」触发（需要 `.env` 里 `NPC_AUTONOMY=on`）。发育期间照常能聊天、问进度，喊「停下」就停。

### 它是怎么“自己发育”的

```
里程碑（milestones.js）     木器 → 石器 → 囤粮 → 床 → 铁器 → 铁甲 → 水桶 → 钻石 → 下界… → 末影龙
    │ 每个里程碑是几个目标，比如「铁器时代」= 背包里要有 iron_pickaxe + iron_sword
    ▼
规划器（planner.js）        obtain(物品, 数量)：没有就倒推怎么弄
    │   能挖的 → 先确保有够格的镐子，再去挖（knowledge.js 记着“铁矿要石镐”）
    │   能烧的 → 先弄原料和燃料，再找/放熔炉烧
    │   能打的 → 找动物/怪物打
    │   能合成的 → 挑最省事的配方，缺的材料递归 obtain
    ▼
技能（skills/）             真正动手：合成、挖矿、冶炼、打猎、放方块、睡觉……
```

一个目标会自动展开成一整棵依赖树，比如“铁镐”：

```
iron_pickaxe ← 3 iron_ingot + 2 stick + 工作台
  iron_ingot ← 烧 raw_iron（燃料：有煤用煤，附近有煤矿去挖，否则烧木板；熔炉 ← 8 cobblestone）
    raw_iron ← 挖 iron_ore（要石镐 ← 3 cobblestone + 2 stick ← 挖 stone（要木镐 ← 木板 + 木棍 ← 砍树））
```

几个关键设计：

- **规划器是“无状态”的**：每一步都只看“背包里现在缺什么”。所以中途死了、被叫停了、程序重启了，重新跑一遍就能接着做，不需要存档
- **挑配方要算真实成本**：白床可以用“3 羊毛 + 3 木板”做，也可以用“白染料 + 一张别的颜色的床”做。只数材料个数会选后者，然后一路推到“要墨囊（只有鱿鱼掉）”走进死胡同。所以规划器会递归估算每种材料从零弄到手的成本，带防循环
- **直接“看到”地下的矿**：mineflayer 收到的区块数据里有所有方块，`findBlocks` 能搜到地下 64 格内的铁矿（钻石搜 160 格），然后挖一条路过去。真人得靠挖矿道碰运气
- **常用材料一次多弄点**：原木至少 5 个、圆石 16 个、煤 8 个，免得做个木棍跑一趟树
- **死了能接着来**：每个目标都带一个“死亡即中断”的信号。死了 → 中断当前步骤 → 重生 → 回死亡地点捡东西 → 重新规划这个目标
- **晚上**：有床就放床睡觉跳过黑夜；睡不了（附近有怪、没空地）就原地往下挖 3 格、封顶，躲到天亮（在地下就不躲，地下白天黑夜一样）
- **不靠大模型**：发育过程全是确定性代码，一次发育几乎不花大模型的钱；大模型只负责聊天和“要不要开始发育”。这是有意的取舍——每一步都问大模型又慢又贵又不稳定

### 测试中踩过的坑（都已修好）

| 现象 | 原因 | 修法 |
|---|---|---|
| 做木镐时“材料齐了却做不了” | 最后才放工作台，工作台把刚备好的木板吃掉了 | 需要工作台的配方，先放工作台再备料 |
| 石镐“做好了”背包里却没有 | 刚打开工作台时服务器偶尔不认第一次合成，材料退回、成品没出 | 合成后数一数，没变多就重试（`craftVerified`） |
| 一直在做白床的染色配方 | 只数材料个数挑配方 | 递归估算真实成本 |
| 在熔炉前被僵尸打死 | 熔炉界面开着时没法换武器还手 | 放好原料就关界面，站岗等，取的时候再开 |
| 晚上被僵尸打死、没床时淹死 | 晚上在地面硬扛 | 床 + 挖坑躲夜 + 受伤就吃到满（饱食度 ≥ 18 才回血） |
| 床“只有半张”、放不下 | 床占两格，普通放方块逻辑只看一格 | 专门的放床：找连续两格空地，确认两半都出现 |
| 挖不到的铁矿一等 90 秒 | 寻路超时才放弃 | 卡住检测：20 秒没挪动就换目标 |
| 地下挖矿时淹死 | 1.18 之后地下有大片含水层，挖开就灌水 | 旁边有水 / 岩浆的矿不挖；氧气低于一半就停下游上去换气 |
| 一直“上去换气”死循环 | **mineflayer 的 bug**：`bot.oxygenLevel` 会被附近鱼、鱿鱼的氧气值覆盖 | 自己只读自己实体的 air_supply（`survival.js` 的 `trackOwnOxygen`） |
| 背包满了挖不了 | 挖矿挖出一堆花岗岩、闪长岩、砂砾 | 快满时自动扔杂物，泥土圆石留一些垫脚 |
| 挖矿慢得离谱（黑曜石一块 75 秒） | **minecraft-data 1.21.6 的数据 bug**：矿石、黑曜石的“材质”写成了 `incorrect_for_wooden_tool` 这种标签，镐子加速完全不算，所有矿都慢 4~8 倍 | 这类方块按“镐子能挖”重新算挖掘时间（`helpers.js` 的 `fixDigTime`） |
| 倒水 / 倒岩浆倒在自己脚边 | 桶是按视线打到的第一个方块放液体的，角度太陡会先打到脚边 | 用桶前先看 `blockAtCursor` 确认对准了目标方块和面；站位不能站在目标方块上 |
| 下界里被疣猪兽顶进岩浆 | minecraft-data 把疣猪兽算成“动物”，本能反应不还手；走路贴着岩浆 | 疣猪兽、岩浆怪、恶魂等也当敌人；寻路时贴着岩浆的格子代价 +50 |
| 死在下界后回不去 | 重生在主世界，离自己搭的门几百格 | 记住主世界这边传送门的位置，死了先走回去再进门 |


## 已知限制

- NPC 只能看见附近的玩家（服务器的实体同步范围内，大约 48 格），离太远「过来」会回“看不到你”
- 走路时不挖不搭：需要搭路、挖洞才能过去的地方会说“过不去”；树太高够不着的原木会跳过
- 砍树只砍够得着的部分，高的树可能会留下树冠
- 合成工具需要附近已经有工作台（它不会自己放）
- 同一时间只做一件事；新任务会取消旧任务
- 公屏聊天只认原版格式 `<玩家名> 消息`，带前缀的插件服暂时识别不到
- 对话记忆在内存里，重启就清空
- 大模型偶尔会理解错，所有动作的结果都会如实回报；不放心的操作可以先用 `NPC_ALLOW_DIG=false` 关掉
